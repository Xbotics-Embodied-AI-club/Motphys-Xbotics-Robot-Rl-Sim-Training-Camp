## 二、总体判定规则

对每讲作业：

- **完成**：该讲全部作业的内容要件逐项满足，且交付物齐全。
- **不通过**：任一红线触发（见 2.1）。
- **待改进**：要件部分缺失，可补交一次后重新判定。

### 2.1 红线（任一触发即该讲不通过）

1. 整段照抄教案 / 官方文档 / 他人作业，无个人理解改写。
2. 实操题（第 7 讲）无实际运行证据（命令、日志、输出目录或曲线任缺）。
3. 提交内容与命令/截图不对应，或冒用他人历史结果。

### 2.2 统一交付形式

每讲提交一份学习文档（可每讲单篇或数讲汇总一篇），要求：

- 含文档题目、姓名/编号、对应讲次（第 X 讲）与作业编号。
- 每道作业的答案标注清楚，实操部分附命令与证据。
- 文档可访问、可复现，引用外部资料注明来源。

## 三、第一周作业完成指标

### 第 1 讲 课程导论：MotrixLab 能做什么

**交付物**：学习文档（含 3 题作答 + 本节总结）。

| 作业 | 内容要件（全部满足才满分） | 判定要点 |
| --- | --- | --- |
| 1. 用自己的话解释 MotrixLab 定位 | 核心定位（面向机器人强化学习的开发平台）+ 主要解决的问题（把环境、仿真、训练、奖励、结果分析组织成可维护的工程流程） | 仅复制教案原句且无展开 → 该题待改进 |
| 2. 平台核心价值 ≥3 点 | 如"统一环境接口与训练入口、配置/日志/模型保存利于复现、环境与算法解耦可扩展"；每点有一句自己的说明 | 只列关键词无说明 → 待改进 |
| 3. 学习目标与预期产出 | 结合课程路径图，≥2 个目标 + 可交付的预期产出（如"跑通 3 个基础控制 Demo 并记录要素"） | 目标不可检查（如"学好强化学习"）→ 待改进 |

**本节总结**：不多于 200 字，能说清"这门课从整体框架到 Demo 实战的路径"。

### 第 2 讲 基础框架总览：分层架构怎么看

**交付物**：学习文档（含架构图、各层说明、分层好处、任务分析、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 画四层架构 + 各层职责 | 用户接口层 / 训练算法层 / 环境实现层 / 物理仿真层，层名与顺序正确，每层职责一句话 | 缺层或将"环境实现层"写成算法职责 → 该题不通过 |
| 2. 分层好处 ≥2 个 | 如职责清晰可独立修改、算法/后端可替换、环境可复用、利于排查定位 | 好处须结合课程内容说明，避免笼统 |

### 第 3 讲 训练环境：EnvCfg、Env、Reward 的关系

**交付物**：学习文档（三个类的角色、CartPole 配置示例、分离设计理解、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 三个类的角色各一句话 | EnvCfg=环境参数；Env=任务流程/交互逻辑；Reward=学习信号 | 三句齐全且不混淆；把 EnvCfg 写成流程逻辑 → 不通过 |
| 2. CartPole EnvCfg 参数 ≥4 个 | 如 model_file、sim_dt/ctrl_dt（或 max_episode_steps）、动作/观测维度、重置噪声、奖励权重；须写"字段名 + 用途或默认值" | 字段须是环境配置语义（把 e.g. learning_rate 混入 → 待改进） |
| 3. 分离设计的好处 | 可复现、不同实验对比、运行时覆盖、便于调试测试 | 至少 2 条，结合课程内容 |

### 第 4 讲 奖励函数：为什么奖励决定训练成败

**交付物**：学习文档（设计原则、稀疏/稠密对比、奖励框架、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 3 个设计原则 + 重要性 | 从"目标一致、信号密度、尺度合理、防漏洞、方向明确、可解释"中选 3；每条说明不满足会怎样 | 只列原则名不解释 → 待改进 |
| 2. 稀疏/稠密对比 + 倒立摆案例 | 说清"倒下 -1 / 不倒 0"是稀疏奖励；训练难点（几乎无正信号，随机探索难获得反馈）；给出稠密化思路（如按角度偏差给连续惩罚） | 未分析案例或无视难点 → 该题不通过 |
| 3. 为"走到目标点"设计奖励框架 | 含任务奖励（接近/到达）+ 辅助/约束（速度、能耗、动作平滑）+ 成功奖励；公式或伪代码；权重量级合理 | 只有"到目标 +1 否则 0"且无中间信号 → 待改进；奖励可被明显刷分（如只奖速度不看方向）→ 待改进 |

## 四、第二周作业完成指标

> **第二周作业结构（按讲设置，见《课后作业选择题-第二周》）：**
> 1. **知识自测**：每讲 10 道选择题（共 30 题），答案表随文件提供，供学员自查、助教快速批改。
> 2. **应用/代码题**：第 5 讲为字段归类 + override 改错；第 6 讲为 `simple_walker` 接入代码填空（下表"作业 3"对应内容照旧判定：装饰器参数、环境名一致、方法名正确、import 链完整，任一错误 → 不通过）。
> 3. **实操必做（红线）**：第 7 讲跑通 CartPole 训练闭环，提交三项运行证据（输出目录截图、TensorBoard 曲线截图 + 趋势结论、play.py 加载命令 + 结果）；无实际运行证据 → 该讲不通过。
>
> 选择题为自测项；判定重心在应用/代码题与实操证据，仍按本表第 5~7 讲的红线与判定要点执行。

### 第 5 讲 配置系统：环境配置与训练配置怎么协作

**交付物**：学习文档（分工、解耦原因、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. EnvCfg 与 RLCfg 分工 | EnvCfg=环境/仿真/任务侧（motrix_envs）；RLCfg=训练/算法侧（motrix_rl）；解释"解耦"：同一环境可换算法，同一算法可服务多环境 | 两侧内容写反 → 不通过 |
| 2. 为什么用"配置类默认值 + 注册机制"而非写死 | ≥2 条：可复现、实验可对比、不改代码换参数/换任务、覆盖机制 | 只答"方便"未展开 → 待改进 |

### 第 6 讲 注册系统：新环境如何接入框架

**交付物**：学习文档（分工、顺序问题、代码框架、import 链、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 两套注册表分工与协作 | `motrix_envs.registry`：@envcfg + @env，make 入口；`motrix_rl.registry`：@rlcfg（env+frame+backend）；同一任务名串起两侧 | 分工或协作关系说错 → 不通过 |
| 2. 未先注册 envcfg 就注册 env 的后果 | 注册顺序依赖：@env 时找不到对应配置 → 导入/运行时报错（找不到任务配置）；通过 import 链保证"先 cfg 后 env" | 未提及"顺序 + 后果（找不到配置报错）"→ 待改进 |
| 3. simple_walker 接入代码 | a) cfg.py：@registry.envcfg("simple_walker") + EnvCfg 子类 + ≥3 个任务特有字段；b) 实现类：@registry.env("simple_walker","np") + 继承基类 + 三个抽象方法名正确（apply_action / update_state / reset）；c) import 链：在哪级 __init__.py 加 `from . import simple_walker_np`，RL 侧在 cfgs.py 加 @rlcfg | 装饰器参数、环境名不一致或方法名错误（写成 step/act）→ 不通过 |

### 第 7 讲 训练流程：从 train.py 到模型保存

**交付物**：学习文档（流程图、训练命令、运行证据、TensorBoard 分析）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 简化流程图 | CLI 解析 → RL 配置加载 → 环境创建 → SKRL 包装 → Agent 构建 → Trainer 执行，顺序正确 | 环节缺失或顺序颠倒 → 待改进 |
| 2. 训练 CartPole 并分析 | ①完整训练命令（含 --env cartpole）；②运行证据：输出目录 `runs/cartpole/…`（checkpoints 或 TensorBoard 事件文件）；③TensorBoard 曲线（reward/loss）截图 + 趋势结论（如收益上升趋于稳定、训练初期抖动等） | 无实际运行证据（无输出目录/曲线/日志）→ 该题不通过；命令与截图 env 名不一致 → 不通过 |

**最小训练规模建议**：CartPole 默认 `max_env_steps=10_000_000` 全量训练耗时长；助教对"跑通"的判定基准建议为 ≥1 个 episode 完成训练闭环、日志目录存在、能启动 TensorBoard 并出图、可调用 `play.py` 加载任一 checkpoint 演示。该基准应统一口径后通知学员（明确"不要求训满 10M 步"）。

## 五、与《周报评审标准》的衔接

- 第一周作业以文案/设计为主，按"理论学习周报"评审（原理总结、练习案例、误区分析必交）。
- 第 7 讲实操后，涉及训练、调参、结果的周报按"项目实践周报"评审，需满足奖励函数截图、效果视频、至少三组实验曲线等硬门槛；前两周若尚未到实验阶段，不强制视频/曲线，但第 7 讲训练证据为必交。

## 六、使用建议

- 发布题目时：可将每讲"作业"列出，把"内容要件"作为提交提醒，"判定要点"供自查。
- 助教判定时：逐项打勾，任一红线即整讲不通过；"待改进"项允许一次补交。
- 范围后续：本指标按同样的模板扩展到第三、四周（第 8、9 讲）后，即可覆盖完整"前四周"评审。
