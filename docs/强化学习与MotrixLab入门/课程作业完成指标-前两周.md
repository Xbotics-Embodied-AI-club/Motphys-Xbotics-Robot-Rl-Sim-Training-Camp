# 第五期课程作业完成指标：前两周

> 适用范围：第五期「强化学习与 MotrixLab 入门」第 1~7 讲的配套题库与作业判定；第一周第 1~4 讲，第二周第 5~7 讲。
> 用途：每讲作业的确定性完成指标，供学员自查、助教逐项判定。
> 评审口径：与《周报评审标准》一致——证据完整才达标，内容多少与"训练最终成功"不能替代证据。
> 本页只约定前两周题库与作业的判定，不将其他期八周排课、《每日一题》覆盖关系或教案全面检查结论视作第五期已验证事实。

## 一、总体判定规则

对每讲作业：

- **完成**：该讲全部作业的内容要件逐项满足，且交付物齐全。
- **不通过**：任一红线触发（见 1.1 及第二周各讲判定）。
- **待改进**：要件部分缺失，可补交一次后重新判定。

### 1.1 红线（任一触发即该讲不通过）

1. 整段照抄教案 / 官方文档 / 他人作业，无个人理解改写。
2. 第 6 讲 `simple_walker` 代码题装饰器参数或环境名不一致、三个抽象方法名错误（写成 `step`/`act`）、import 链缺失，或无法给出对应的验证命令。
3. 第 7 讲缺任一项实际运行证据（输出目录、TensorBoard 曲线与分析、`play.py` 加载命令及结果），或命令、截图与环境名不对应。
4. 提交内容与命令/截图不对应，或冒用他人历史结果。

### 1.2 统一交付形式

每讲提交一份学习文档（可每讲单篇或数讲汇总一篇），要求：

- 含文档题目、姓名/编号、对应讲次（第 X 讲）与作业编号。
- 每道作业的答案标注清楚，实操部分附命令与证据。
- 文档可访问、可复现，引用外部资料注明来源。

## 二、第一周作业完成指标

### 第 1 讲 课程导论：MotrixLab 能做什么

**交付物**：学习文档（含 3 题作答 + 本节总结）。

| 作业 | 内容要件（全部满足才满分） | 判定要点 |
| --- | --- | --- |
| 1. 用自己的话解释 MotrixLab 定位 | 核心定位（面向机器人强化学习的开发平台）+ 主要解决的问题（把环境、仿真、训练、奖励、结果分析组织成可维护的工程流程） | 仅复制教案原句且无展开 → 该题待改进 |
| 2. 平台核心价值 ≥3 点 | 如"统一环境接口与训练入口、配置/日志/模型保存利于复现、环境与算法解耦可扩展"；每点有一句自己的说明 | 只列关键词无说明 → 待改进 |
| 3. 学习目标与预期产出 | 结合课程路径图，≥2 个目标 + 可交付的预期产出（如"跑通 3 个基础控制 Demo 并记录要素"） | 目标不可检查（如"学好强化学习"）→ 待改进 |

**本节总结**：不多于 200 字，能说清"这门课从整体框架到 Demo 实战的路径"。

### 第 2 讲 基础框架总览：分层架构怎么看

**交付物**：学习文档（含架构图、各层说明、分层好处、任务分析、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 画四层架构 + 各层职责 | 用户接口层 / 训练算法层 / 环境实现层 / 物理仿真层，层名与顺序正确，每层职责一句话 | 缺层或将"环境实现层"写成算法职责 → 该题不通过 |
| 2. 分层好处 ≥2 个 | 如职责清晰可独立修改、算法/后端可替换、环境可复用、利于排查定位 | 好处须结合课程内容说明，避免笼统 |
| 3. 选一个任务做四层分析 | 同一任务在每层的对应（命令入口、算法/P P O、环境要素、仿真） | 逐层都有对应描述才通过 |

### 第 3 讲 训练环境：EnvCfg、Env、Reward 的关系

**交付物**：学习文档（三个类的角色、CartPole 配置示例、分离设计理解、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 三个类的角色各一句话 | EnvCfg=环境参数；Env=任务流程/交互逻辑；Reward=学习信号 | 三句齐全且不混淆；把 EnvCfg 写成流程逻辑 → 不通过 |
| 2. CartPole EnvCfg 参数 ≥4 个 | 如 model_file、sim_dt/ctrl_dt（或 max_episode_steps）、动作/观测维度、重置噪声、奖励权重；须写"字段名 + 用途或默认值" | 字段须是环境配置语义（把 e.g. learning_rate 混入 → 待改进） |
| 3. 分离设计的好处 | 可复现、不同实验对比、运行时覆盖、便于调试测试 | 至少 2 条，结合课程内容 |

### 第 4 讲 奖励函数：为什么奖励决定训练成败

**交付物**：学习文档（设计原则、稀疏/稠密对比、奖励框架、总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 3 个设计原则 + 重要性 | 从"目标一致、信号密度、尺度合理、防漏洞、方向明确、可解释"中选 3；每条说明不满足会怎样 | 只列原则名不解释 → 待改进 |
| 2. 稀疏/稠密对比 + 倒立摆案例 | 说清"倒下 -1 / 不倒 0"是稀疏奖励；训练难点（几乎无正信号，随机探索难获得反馈）；给出稠密化思路（如按角度偏差给连续惩罚） | 未分析案例或无视难点 → 该题不通过 |
| 3. 为"走到目标点"设计奖励框架 | 含任务奖励（接近/到达）+ 辅助/约束（速度、能耗、动作平滑）+ 成功奖励；公式或伪代码；权重量级合理 | 只有"到目标 +1 否则 0"且无中间信号 → 待改进；奖励可被明显刷分（如只奖速度不看方向）→ 待改进 |

## 三、第二周作业完成指标

> **第二周作业结构（见《课后作业选择题-第二周》）：**
> 1. **知识自测**：每讲 10 道选择题（共 30 题），答案表随题库提供，供学员自查、助教快速批改。
> 2. **应用/代码题**：第 5 讲字段归类 + override 改错；第 6 讲 `simple_walker` 接入代码填空（配置、环境实现、import 链及验证命令）。
> 3. **实操必做（红线）**：第 7 讲 CartPole 训练闭环，提交输出目录截图、TensorBoard 曲线截图与趋势结论、`play.py` 加载命令与结果，共三项运行证据。
>
> 选择题为知识自测，不以选择题分数代替应用/代码题及实操证据；第 5~7 讲按下表与红线逐项判定。

### 第 5 讲 配置系统：环境配置与训练配置怎么协作

**交付物**：学习文档（EnvCfg 与 RLCfg 分工、解耦与配置机制、应用题 (a)(b) 作答、本节总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. EnvCfg 与 RLCfg 分工 | EnvCfg=环境/仿真/任务侧（motrix_envs）；RLCfg=训练/算法侧（motrix_rl）；解释"解耦"：同一环境可换算法，同一算法可服务多环境 | 两侧内容写反 → 不通过 |
| 2. 为什么用"配置类默认值 + 注册机制"而非写死 | ≥2 条：可复现、实验可对比、不改代码换参数/换任务、覆盖机制 | 只答"方便"未展开 → 待改进 |
| 3. 应用题 (a)：8 个字段归类 | `EnvCfg`：`model_file`、`sim_dt`、`render_spacing`、`max_episode_seconds`；`RLCfg`：`learning_rate`、`num_envs`、`rollouts`、`ratio_clip`，两侧各 4 个 | 漏项或个别分错 → 待改进；将环境侧与训练侧整体写反 → 不通过 |
| 4. 应用题 (b)：override 改错 | `env_cfg_override={"not_exist_param": 2.0}` 中字段不存在；`registry.make()` 创建默认配置后检查属性（`hasattr`），抛 `ValueError`，而不是静默添加字段 | 未指出不存在的字段、触发位置或异常类型 → 待改进 |

### 第 6 讲 注册系统：新环境如何接入框架

**交付物**：学习文档（两套注册表的分工与顺序、`simple_walker` 代码题 (a)~(d)、本节总结）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 两套注册表分工与协作 | `motrix_envs.registry`：`@envcfg` + `@env`、`make` 入口；`motrix_rl.registry`：`@rlcfg`（环境名 + 训练框架 + backend）；同一任务名串起两侧 | 分工或协作关系说错 → 不通过 |
| 2. 未先注册 envcfg 就注册 env 的后果 | 注册顺序依赖：`@env` 时找不到对应配置 → 导入/运行时报错；通过 import 链保证先 cfg 后 env | 未提及顺序和找不到配置的后果 → 待改进 |
| 3. 代码题 (a)：配置类 | `cfg.py` 的 `@registry.envcfg("simple_walker")`、`EnvCfg` 子类、≥3 个任务特有字段及各字段用途 | 装饰器参数/环境名错误 → 不通过；字段或用途不足 → 待改进 |
| 4. 代码题 (b)：环境实现 | `simple_walker_np.py` 用 `@registry.env("simple_walker", "np")` 装饰继承基类的实现类；列出 `apply_action(actions, state)`、`update_state(state)`、`reset(data)` | 环境名/后端错误，或方法名写成 `step`/`act` → 不通过 |
| 5. 代码题 (c)：import 链及 RL 配置 | 分类 `__init__.py` 加 `from . import simple_walker`；`simple_walker/__init__.py` 加 `from . import simple_walker_np`（确保配置类与实现类的装饰器执行）；`motrix_rl/cfgs.py` 用 `@rlcfg("simple_walker")` 注册 `PPOCfg` 子类 | import 链缺一环或三处环境名不一致 → 不通过 |
| 6. 代码题 (d)：验证命令 | `uv run scripts/train.py --env simple_walker`；说明环境名与三处注册名一致 | 缺命令或环境名不一致 → 不通过；本题要求写出命令，不要求实际训练 `simple_walker` |

### 第 7 讲 训练流程：从 train.py 到模型保存

**交付物**：学习文档（流程图、训练与 TensorBoard 命令、下表三项 CartPole 运行证据及分析）。

| 作业 | 内容要件 | 判定要点 |
| --- | --- | --- |
| 1. 简化流程图 | CLI 解析 → RL 配置加载 → 环境创建 → SKRL 包装 → Agent 构建 → Trainer 执行，顺序正确 | 环节缺失或顺序颠倒 → 待改进 |
| 2. 输出目录与训练闭环 | 完整训练命令（如 `uv run scripts/train.py --env cartpole`）；≥1 个 episode 完成训练闭环；截图显示 `runs/cartpole/<时间戳>_PPO/`，内含 `checkpoints/` 或 `events.out.tfevents.*` | 无训练命令或输出目录截图 → 不通过；命令与截图的环境名不一致 → 不通过 |
| 3. TensorBoard 分析 | `uv run tensorboard --logdir runs/cartpole`；reward/loss 曲线截图与一句话趋势结论 | 无曲线截图、命令或趋势结论 → 不通过 |
| 4. 推理演示 | `uv run scripts/play.py --env cartpole --policy <checkpoint路径>` 成功加载任一 checkpoint；提交实际命令及一句话运行结果 | 未提供可加载的 checkpoint 与实际加载命令/结果 → 不通过；命令与截图环境名不一致 → 不通过 |

**最小训练规模**：不要求训满 `max_env_steps=10_000_000`；须满足 ≥1 个 episode 完成训练闭环、日志目录存在、TensorBoard 能启动并出图、`play.py` 能加载任一 checkpoint 演示。仅有目录或曲线而缺第三项推理演示不能判定完成；无实际运行证据（无输出目录/曲线/命令日志）→ 该讲不通过。

## 四、与《周报评审标准》的衔接

- 第一周作业以文案/设计为主，可按"理论学习周报"评审（原理总结、练习案例、误区分析必交）。
- 第 7 讲的作业红线以本页三项运行证据为准；若另行提交涉及训练、调参、结果的"项目实践周报"，仍须按《周报评审标准》提供奖励函数截图、效果视频、至少三组实验曲线等必交证据，不能以本讲作业完成代替周报评优。

## 五、使用建议

- 发布题目时：将每讲"作业"列出，把"内容要件"作为提交提醒，"判定要点"供自查。
- 助教判定时：逐项打勾，任一红线即整讲不通过；"待改进"项允许一次补交。
- 本指标仅覆盖前两周（第 1~7 讲）；后续讲次的排课与评审范围须另行核对，不沿用其他期的周次推断。
