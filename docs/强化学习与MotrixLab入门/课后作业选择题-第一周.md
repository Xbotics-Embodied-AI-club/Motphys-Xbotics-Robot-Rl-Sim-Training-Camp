## 第 2 讲 基础框架总览：分层架构怎么看（10 题）

1. MotrixLab 整体结构从上到下分为哪四层？
   - A. 用户接口层 → 训练算法层 → 环境实现层 → 物理仿真层
   - B. 环境实现层 → 用户接口层 → 物理仿真层 → 训练算法层
   - C. 数据层 → 算法层 → 接口层 → 仿真层
   - D. 物理仿真层 → 环境实现层 → 训练算法层 → 用户接口层

2. `train.py`、`play.py`、`view.py` 这类脚本属于哪一层？
   - A. 用户接口层
   - B. 训练算法层
   - C. 环境实现层
   - D. 物理仿真层

3. 用户接口层的核心职责是？
   - A. 实现任务逻辑（观测、奖励、终止条件）
   - B. 负责启动流程：解析参数、加载配置、创建环境、启动训练或测试
   - C. 计算物理碰撞
   - D. 更新网络参数

4. 训练算法层（如 PPO）主要负责？
   - A. 定义任务目标
   - B. 数据采样、损失计算、参数更新等策略学习工作
   - C. 推进物理仿真
   - D. 解析用户命令行

5. 关于训练算法层与环境的关系，教案强调？
   - A. 算法需要了解每个机器人模型的关节细节
   - B. 算法只需要环境返回标准强化学习信息：观测、奖励、终止标志等
   - C. 算法必须自己处理物理仿真步长
   - D. 算法与机器人模型强耦合

6. 环境实现层中，`Env` 负责的是？
   - A. 定义环境参数（模型文件、步长、奖励权重等）
   - B. 实现任务逻辑：如何接收动作、推进仿真、构造观测、判断任务结束
   - C. 生成学习信号
   - D. 物理碰撞检测

7. 用分层视角阅读 MotrixLab 项目，第一步应该怎么做？
   - A. 从头到尾逐行读完每个文件
   - B. 先运行所有官方 Demo
   - C. 判断文件属于哪一层，再看它承担什么职责
   - D. 先读物理引擎源码

8. 机器人在仿真里一开始就抖动、穿模、爆炸，应该优先检查哪一层？
   - A. 只把 PPO 学习率调大
   - B. 物理仿真层和环境参数
   - C. 命令行参数格式
   - D. 换一个奖励权重

9. 下列哪项典型属于**环境实现层**的问题？
   - A. 命令行参数写错
   - B. 观测缺关键信息、奖励方向错误、终止条件过严
   - C. PPO 配置不合理
   - D. 机器人仿真不稳定

10. 一次训练的正确流转顺序是？
    - A. 用户命令 → 训练入口 → 配置和注册 → 环境创建 → 算法采样 → 物理仿真 → 奖励反馈 → 策略更新
    - B. 训练入口 → 算法采样 → 用户命令 → 环境创建 → 物理仿真
    - C. 环境创建 → 配置和注册 → 用户命令 → 算法采样 → 策略更新
    - D. 物理仿真 → 奖励反馈 → 算法采样 → 环境创建 → 训练入口

## 第 3 讲 训练环境：EnvCfg、Env、Reward 的关系（10 题）

   - B. EnvCfg 管流程，Env 管参数，Reward 管目标
   - C. EnvCfg 管目标，Reward 管参数，Env 管流程
   - D. 三者职责完全相同

   - B. 改参数要改代码、不同实验难以对比、代码难以复用和测试

   - D. 不需要再写奖励

3. `EnvCfg` 中 `sim_dt` 的含义是？

   - B. 控制步长（秒）
   - C. 训练总时长
   - D. 网络参数更新的间隔

4. `EnvCfg` 的"四大作用"**不包括**下列哪项？
   - A. 配置集中化
   - B. 实验可复现
   - C. 便于运行时覆盖

6. `Env` 的核心职责是？
   - A. 定义环境所需的全部参数

7. `Env.step(action)` 的标准返回值是？

   - D. 先读所有 import 再读逻辑

9. `Env.reset()` 的职责是？

## 第 4 讲 奖励函数：为什么奖励决定训练成败（10 题）

1. 关于 Reward 的本质，最准确的说法是？
   - A. 把任务目标转成数值信号；算法只会优化 reward，不懂真实目标
   - B. 是给人类看的日志
   - C. 描述机器人模型的关节细节
   - D. 决定物理仿真的步长

2. 教案提出的奖励设计六大原则，**不包括**下列哪项？
   - A. 目标一致
   - B. 信号密度
   - C. 尺度合理
   - D. 数值越大越好

3. 任务要求"抓取物体"，但奖励只写 `reward = -distance_to_object`（只奖励接近），主要问题是什么？
   - A. 奖励与真实目标不一致，模型可能学到只接近、不抓取
   - B. 训练一定会失败，完全无法收敛
   - C. 没有问题，靠近自然就能完成抓取
   - D. 会导致物理仿真崩溃

4. 下列哪一项是"稀疏奖励"的典型示例？
   - A. 任务成功给 1，否则全给 0
   - B. 每一步按距离变化给出连续反馈
   - C. 对抖动动作施加惩罚
   - D. 成功后额外加分

5. 奖励惩罚量级过大（如 `-100 * abs(action)`）的典型后果是？
   - A. 模型学会不动
   - B. 模型动作更平滑
   - C. 训练收敛更快
   - D. 观测信号更稳定

6. 奖励只给末端速度 `abs(velocity)`，智能体可能通过什么方式刷高分？
   - A. 静止不动
   - B. 不断抖动以获得速度分
   - C. 匀速直线靠近目标
   - D. 减少动作能耗

7. 奖励项互相打架（如先 `speed * 2.0` 后又 `- speed * 3.0`）的后果是？
   - A. 模型不知道该学什么
   - B. 训练速度翻倍
   - C. 奖励变得更加可解释
   - D. 对学习没有任何影响

8. 奖励设计的"可解释"原则要求？
   - A. 每一项奖励都对应明确的任务目标
   - B. 表达式越复杂越好
   - C. 奖励项越多越好
   - D. 奖励来源对学员隐藏

9. 出现"总 reward 在上升，但任务实际失败"时，最合理的排查做法是？
   - A. 只看总 reward 是否超过阈值
   - B. 看 success rate 与 reward breakdown，警惕在刷辅助奖励项
   - C. 直接加大所有奖励权重
   - D. 缩短训练步数

10. 关于训练过程的行为观察，教案强调？
    - A. reward 曲线可以完全替代行为观察
    - B. 每周至少看一次训练过程的行为视频，检查是否有预期动作之外的"作弊"行为
    - C. 只要曲线收敛就代表任务成功
    - D. 边界状态（成功/失败/超时边界）无需检查
