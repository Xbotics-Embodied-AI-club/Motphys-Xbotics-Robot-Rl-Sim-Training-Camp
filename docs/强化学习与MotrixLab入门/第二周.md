# 第五期第二周：课程内容与作业（第 5～7 讲）

[返回课程目录](./index.md) · [第一周](./第一周.md)

本周学习环境配置与训练配置的协作、新任务的注册方式，以及从训练入口到模型保存和演示的完整流程。每讲有 10 道选择题自测；第 5、6 讲另有应用或代码题，第 7 讲必须提交真实运行证据。完整题目与参考答案见[第二周课后作业](./课后作业选择题-第二周.md)，详细判定口径见[前两周作业完成指标](./课程作业完成指标-前两周.md#三、第二周作业完成指标)。

## 第 5 讲：配置系统——环境配置与训练配置怎么协作

- **学习重点**：`EnvCfg` 管环境、仿真与任务；`RLCfg` 管训练与算法。理解默认值、注册和运行时覆盖如何支持实验复现。
- **课程资料**：[课程教案](https://ucnj8k63v5wn.feishu.cn/docx/KWb4dycPQo5eoZxkgVrcFdutn1c)；视频文件名为 `Lesson5.mp4`，原稿未提供在线地址。
- **应用题 (a)**：将 `model_file`、`learning_rate`、`sim_dt`、`num_envs`、`rollouts`、`render_spacing`、`ratio_clip`、`max_episode_seconds` 分别归入 `EnvCfg` 或 `RLCfg`，说明每个字段的用途及配置解耦的好处。
- **应用题 (b)**：分析以下覆盖操作会发生什么：

  ```python
  env = registry.make(
      name="my-env",
      sim_backend="np",
      num_envs=256,
      env_cfg_override={"not_exist_param": 2.0},
  )
  ```

  指出不存在的字段，以及配置实例化后进行属性检查为何会触发 `ValueError`，而不是静默添加字段。
- **交付与自查**：提交字段归类、改错分析、配置默认值和注册/覆盖机制的理解、本节总结；还需说明采用配置类与注册机制而非硬编码的至少 2 个理由。详见[第 5 讲指标](./课程作业完成指标-前两周.md#第-5-讲-配置系统-环境配置与训练配置怎么协作)和[选择题与应用题](./课后作业选择题-第二周.md#第-5-讲-配置系统-环境配置与训练配置怎么协作-10-题)。

## 第 6 讲：注册系统——新环境如何接入框架

- **学习重点**：`motrix_envs.registry` 管环境配置、环境实现及创建入口，`motrix_rl.registry` 管训练配置；导入模块会触发装饰器，先注册配置再注册环境实现。
- **课程资料**：[课程教案](https://my.feishu.cn/docx/FcEhd1q5KoYouwxJW9YcQS3Fn9d)；视频文件名为 `Lesson6.mp4`，原稿未提供在线地址。
- **代码题**：以 `simple_walker` 为例，在 `cfg.py` 写 `@registry.envcfg("simple_walker")`、`EnvCfg` 子类及至少 3 个任务特有字段和用途；在 `simple_walker_np.py` 写 `@registry.env("simple_walker", "np")`，列出必须实现的 `apply_action(actions, state)`、`update_state(state)`、`reset(data)`；在分类目录和任务目录的 `__init__.py` 分别加入 `from . import simple_walker` 与 `from . import simple_walker_np`，并在 `motrix_rl/cfgs.py` 用 `@rlcfg("simple_walker")` 注册 `PPOCfg` 子类。三处环境名必须一致。
- **验证命令**：`uv run scripts/train.py --env simple_walker`。本讲要求给出命令，不要求实际训练该任务。
- **交付与自查**：提交两套注册表的分工、注册顺序与 import 链、代码框架、字段用途、验证命令和本节总结；装饰器参数或环境名错误、三个抽象方法名错误、import 链缺失、无法给出验证命令均为该讲不通过项。详见[第 6 讲指标](./课程作业完成指标-前两周.md#第-6-讲-注册系统-新环境如何接入框架)和[选择题与代码填空](./课后作业选择题-第二周.md#第-6-讲-注册系统-新环境如何接入框架-10-题)。

## 第 7 讲：训练流程——从 `train.py` 到模型保存

- **学习重点**：命令行解析、RL 配置加载、环境创建、SKRL 包装、Agent 构建与 Trainer 执行，以及日志与 checkpoint 的保存和加载。
- **课程资料**：[课程教案](https://my.feishu.cn/docx/TE06dQwwOoFvC8xly7kcMxs5nUf)；视频文件名为 `Lesson7.mp4`，原稿未提供在线地址。
- **实操必做**：跑通 CartPole 的训练闭环，至少完成 1 个 episode；不要求训满 `max_env_steps=10_000_000`。提交以下三项真实证据：
  1. 训练命令（如 `uv run scripts/train.py --env cartpole`）及 `runs/cartpole/<时间戳>_PPO/` 目录截图；其中应有 `checkpoints/` 或 `events.out.tfevents.*`。
  2. `uv run tensorboard --logdir runs/cartpole` 的 reward/loss 曲线截图及一句话趋势结论。
  3. `uv run scripts/play.py --env cartpole --policy <checkpoint路径>` 成功加载模型的实际命令记录及一句话演示结果。
- **交付与自查**：提交学习文档及简化流程图（CLI 解析 → RL 配置加载 → 环境创建 → SKRL 包装 → Agent 构建 → Trainer 执行）和上述三项证据。缺任一项运行证据、命令与截图环境名不一致或冒用历史结果，该讲不通过。详见[第 7 讲指标](./课程作业完成指标-前两周.md#第-7-讲-训练流程-从-train-py-到模型保存)和[选择题与实操题](./课后作业选择题-第二周.md#第-7-讲-训练流程-从-train-py-到模型保存-10-题)。
