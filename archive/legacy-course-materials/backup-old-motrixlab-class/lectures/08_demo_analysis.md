# 08 Demo 分析方法：如何读懂一个案例

## 本章目标
- 建立分析 Demo 的通用方法
- 能快速拆解一个新案例
- 学会从案例中提炼共性经验

## 一、为什么要学会分析 Demo
对于学习 MotrixLab 来说，Demo 是最好的入口。通过 Demo，你可以直接看到一个任务是如何定义、训练和验证的。

如果只看代码而没有分析方法，就很容易陷入“每个案例都像新项目”的困境。掌握分析方法后，你就能快速识别一个任务的结构。

## 二、分析一个 Demo 的顺序
建议按照以下顺序阅读：
1. 任务目标是什么
2. 状态怎么设计
3. 动作怎么设计
4. 奖励怎么设计
5. 终止条件是什么
6. 训练难点在哪里

## 三、重点关注什么
读 Demo 时，最重要的不是看语法，而是看下面这些要素：
- 这个任务想让机器人做什么
- 需要什么观测信息
- 动作如何作用到环境
- 奖励是如何引导学习的
- 什么情况下会结束一轮 episode

## 四、如何提炼经验
一个 Demo 的价值不仅在于完成当前任务，更在于它提供了可复用的方法，比如：
- 平衡类任务如何设计奖励
- 抓取类任务如何定义接近与成功条件
- 行走类任务如何处理接触和稳定性

## 五、总结
Demo 分析的关键，是把“看代码”变成“看结构”。只要你能回答任务目标、状态、动作、奖励和终止条件这五个问题，就已经具备读懂大多数 Demo 的能力了。
