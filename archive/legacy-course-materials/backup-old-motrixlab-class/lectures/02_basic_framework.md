# 02 基础框架总览：分层架构怎么看

## 本章目标
- 看懂 MotrixLab 的整体分层设计
- 理解各层之间的责任边界
- 建立从上到下的系统视角

## 一、为什么要看分层架构
机器人强化学习项目通常包含多个部分：仿真、控制、训练、日志、可视化等。如果这些内容全部耦合在一起，项目会很难维护，也很难扩展。

MotrixLab 采用分层架构，把不同职责拆分到不同层次中，这样做的好处是：
- 代码更清晰
- 扩展更方便
- 问题更容易定位
- 不同模块可以独立演化

## 二、四层结构概览
MotrixLab 的主要结构可以概括为四层：

### 1. 用户接口层
包含 `train.py`、`play.py`、`view.py` 等入口脚本。

这一层面向用户，负责接收命令、启动流程、调用底层模块。

### 2. 训练算法层
包含 SKRL、RSLRL、PPO、网络结构、优化器等。

这一层负责真正的强化学习训练逻辑。

### 3. 环境实现层
包含 `EnvCfg`、`Env`、`Reward`。

这一层定义任务本身，是环境与奖励的核心。

### 4. 物理仿真层
包含 MotrixSim、MJCF 模型、物理引擎、碰撞检测等。

这一层负责让环境“动起来”，提供真实或近似真实的物理反馈。

## 三、各层之间如何协作
可以把整个流程理解为：

- 用户通过脚本启动任务
- 训练层读取配置并构建算法
- 环境层提供状态、动作和奖励
- 仿真层负责底层物理演算

这样就形成了一个自上而下的闭环：
用户命令 → 训练算法 → 环境交互 → 物理反馈 → 策略更新

## 四、分层设计的好处
这种架构带来的直接收益包括：
- 环境开发者不需要关心训练框架细节
- 算法开发者不需要修改具体任务逻辑
- 新任务可以通过注册方式接入
- 同一环境可以适配不同训练后端

## 五、总结
理解分层架构，是理解 MotrixLab 的第一步。后面的所有内容，比如奖励函数、配置系统、注册机制和训练流程，实际上都是围绕这四层展开的。
