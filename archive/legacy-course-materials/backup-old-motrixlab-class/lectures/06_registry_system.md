# 06 注册系统：新环境如何接入框架

## 本章目标
- 理解注册系统的作用
- 明白新环境如何被框架自动识别
- 学会从扩展性角度看项目结构

## 一、为什么需要注册系统
如果每加入一个新环境都要手动修改主流程，项目就会越来越难维护。注册系统的目的，就是让新组件以统一方式接入框架。

## 二、注册系统的核心思想
MotrixLab 使用装饰器风格的注册方式，把不同组件登记到系统中。这样做的好处是：
- 代码更解耦
- 新任务接入更方便
- 主流程不需要频繁修改

## 三、常见的注册对象
通常会注册以下内容：
- 环境配置类
- 环境实现类
- RL 配置类

这些对象注册后，框架就能根据名称或类型自动查找并实例化。

## 四、新环境如何接入
一个新环境接入框架时，通常需要：
1. 定义配置类
2. 定义环境实现类
3. 编写奖励逻辑
4. 使用注册装饰器完成注册
5. 在启动脚本中通过名称调用

## 五、注册系统的价值
注册系统最大的价值是可扩展性。它使得：
- 新环境更容易加入项目
- 多个任务可以并存
- 框架核心逻辑保持稳定

## 六、总结
注册系统是 MotrixLab 的“连接器”。它把配置、环境和训练逻辑连接起来，让框架既统一又灵活。
